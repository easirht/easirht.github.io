Personal Project — Predictive Maintenance & Vibration Analysis

Bearing Fault Diagnosis: Cross-Fault-Size Generalization (CWRU)

Studied whether bearing fault classifiers that look accurate on the CWRU dataset still work when the fault size changes. Cross-load testing gave 100% accuracy, but training on one fault size and testing on another dropped macro-F1 to roughly 0.25–0.57. Envelope-spectrum features based on bearing fault frequencies (BPFO, BPFI, BSF) raised Random Forest macro-F1 from 0.26 to 0.68 in one direction (0.014 in → 0.007 in) and did not help in the other. Includes a deployed Streamlit monitoring dashboard.

Python scikit-learn Envelope Spectrum Vibration Analysis Streamlit
View Project Details →

Using the CWRU 12 kHz drive-end data (loads 0–3 HP, normal, inner race, ball and outer race faults at 0.007 and 0.014 in), I cut signals into overlapping windows and extracted time-domain features (RMS, kurtosis, crest factor and others) and envelope-spectrum features: band-pass filtering, Hilbert envelope, and relative energy at the fault frequencies computed from each load's shaft speed. Models were a Random Forest and an RBF SVM, evaluated with leave-one-load-out and then cross-fault-size splits, repeated over 10 seeds. Normal recordings are shared between sizes, so each was split in halves to avoid leakage.

The result is mixed, and I report it that way: envelope features helped strongly when training on 0.014 in and testing on 0.007 in, but not in the reverse direction, and combining them with time-domain features did not beat envelope features alone. Limitations are documented in the repository: each (size, load, class) is a single recording, so the standard deviations reflect only window sampling and model randomness; only two fault sizes were used; the SVM was not tuned; and the dashboard's demo model is trained on all data, so it is a workflow demo rather than a valid test.

Personal Project — Physics-Informed Machine Learning

Physics-Informed Neural Networks for 1D Heat Conduction

Trained a PINN on the transient heat equation using only the governing equation and boundary/initial conditions (0.31% relative L2 error), benchmarked it against finite-difference solvers, and used it to recover an unknown thermal diffusivity from 30 noisy measurements (0.16% error on clean data, 2.9% at 5% noise). Everything runs on a CPU laptop.

PyTorch PINN Heat Transfer Finite Differences Inverse Problems
View Project Details →

The forward PINN (three hidden layers of 32 tanh units, 5,000 Adam epochs) needs no simulation data. I compared it with explicit FTCS and Crank-Nicolson solvers against the analytical solution. On this simple linear problem the classical solvers win clearly: Crank-Nicolson on an 11 × 11 grid matches the PINN's error (about 3e-3) in roughly 0.3 ms versus 42–65 s of PINN training, and at 161 × 161 it reaches 1.2e-5. The PINN is therefore not a competitive forward solver here, and I report that as a result.

The inverse problem is where the PINN is useful: with the diffusivity as a trainable parameter, starting from a guess five times too large, it recovers the true value in a single training run. Limitations are documented in the repository: every number comes from a single random seed, the measurements are synthetic, boundary and initial conditions are assumed known exactly, and the network was not tuned.

Personal Project — Deep Learning

Animal Image Classifier — Transfer Learning with MobileNetV2

Fine-tuned MobileNetV2 on a 10-class animal dataset (about 26,000 images) and evaluated it on a fixed, leak-free test split: 97.4% accuracy and 0.971 macro-F1 on 2,619 held-out images, in a 24 MB model.

TensorFlow / Keras Transfer Learning MobileNetV2 AdamW + Cosine LR Model Evaluation
View Project Details →

I compared a baseline recipe (Adam, constant learning rate, last 30 layers fine-tuned) with an improved one (AdamW, cosine-decay learning rate, last 50 layers with frozen BatchNorm, stronger augmentation). Test accuracy rose from 96.9% to 97.4% and macro-F1 from 0.963 to 0.971, but a paired McNemar test (p = 0.12) shows the gain is within noise, which suggests MobileNetV2 is close to the ceiling for this dataset.

Along the way I found and fixed an evaluation bug: a reshuffled test set had misaligned labels and predictions, giving impossible Top-2 accuracy. I rebuilt the pipeline with an explicit stratified split and a single unshuffled prediction pass. The most confident errors turned out to include dataset labeling mistakes (a dragonfly and a beetle labeled as butterfly, a horse labeled as cow), so the reported accuracy is probably a slight underestimate.

Academic Project

Three-Axis Robotic Arm

Designed and built a robotic arm with three-axis rotation using servo motors and an Arduino Uno, including full circuit design and button-based control logic.

Arduino Uno Servo Motors Circuit Design
View Project Details →

The arm uses three servo motors, each independently controlled through a dedicated push-button pair wired to the Arduino Uno's digital pins — one button to rotate a joint forward, the other in reverse — rather than a single continuous-motion controller. The circuit was built and tested on a breadboard before being wired into the final frame, with each servo's power draw and signal line kept separate to avoid voltage drops affecting motion accuracy. The build served as a hands-on introduction to embedded control logic — sequencing multiple actuators from simple digital inputs — which is the same basic principle scaled up in most automation and robotics systems.

Team Project — Formula Kart Design Challenge

Go-Kart Quality Control — Team Annexe RUET

Led quality control for the design and manufacturing of a Go-Kart competing in the FKDC — materials selection, dimensional analysis, and component sourcing, from workshop fabrication through to the final test run.

Quality Control Dimensional Analysis ANSYS FKDC
View Project Details →

As QC Team Lead, I was responsible for the chassis and drivetrain components standing up to real competition conditions rather than just passing a bench test. That meant checking incoming materials and dimensions against the design tolerances before parts went into the frame, tracking down fit issues during welding and assembly (visible in the late-night build sessions), and sourcing components on a tight budget without compromising the safety-critical parts — steering, brakes, and the roll structure. The kart competed at the Formula Kart Design Challenge (FKDC) in Coimbatore, India, representing Team Annexe RUET, and the team used ANSYS for structural checks on the chassis design before fabrication began.
